# E1 — Can the machine do it?

**Status:** scaffold built; Claim 001 fixture complete; **not yet run against a model.**
**Date:** 2026-08-22 (prompt contract `e1-v2`)
**Spec:** `product/v1-prd.md` §12.2. **Gate amendment:** `docs/decision_log.md` D-033.
**Scope:** one claim file, three documents, one planted conflict pair.

---

## 1. The question

> Can an LLM accurately extract span-cited facts from realistic claim narratives
> and propose differences between them **without inventing any**?

That is the whole question. E1 does not ask whether the output is useful, whether
an adjuster would trust it, or whether the differences it finds are the ones that
matter. Those are the §12 human study's questions, and E1 cannot answer them.

## 2. What E1 is NOT

This section is longer than the last one on purpose, because the most likely way
to waste this experiment is to read more into its result than it contains.

**E1 does not test materiality, and the runner cannot be made to.**
`src/evaluation/metrics.py` refuses any metric name containing `material`,
`importance`, `severity`, `suspicion`, or `credibility`. The reason is recorded
in the decision log's own closing argument: *a model can score extremely well
against a category that is incoherent.* If we author the gold materiality labels
and the model reproduces them, we will have measured our own consistency and
called it performance — and that failure is invisible from inside the technical
work. `materiality_intent` exists in the gold answers as metadata for the §12
study only.

**E1 does not lift D-014's gate.** D-014 gates Phase 5 onward on the §12 human
study. E1 informs the architecture; it does not substitute for asking whether the
thing is worth doing. A clean E1 result changes nothing about that.

**E1 does not measure real-world performance.** Every fixture is synthetic. Per
D-003 the labels record *what we planted*, and every fixture and every evaluation
output says so in the artifact itself.

**E1 does not test:** model choice or prompt optimisation (one model, one prompt
version, no chaining, no retrieval), the injury/medical layer, photographs or
diagrams, the coded half of a police report (D-030), long-term adoption, or the
anchoring risk — for which there is no technical mitigation and which a *better*
product makes worse.

## 3. Architecture under test

Nine stages, executed in order, once. Two call a model; seven are code.

```
[1] INGEST          validate the bundle; refuse malformed input          code
[2] ENUMERATE       documents -> passages, routed by structure_class     code
[3] READ + DERIVE   structured fields, delays, counts, checks            code
[4] EXTRACT         passage -> (assertion, asserter, span)               LLM  x3
[5] RESOLVE         verify every span; unresolved -> DROP                code   <-- the gate
[6] NORMALIZE       dates, money, quantities; vague stays vague          code
[7] TIMELINE        sort both axes from normalised dates                 code
[8] DIFFERENCES     (a) deterministic pairs 4 / 10                       code
                    (b) propose over Facts only, never passages          LLM  x1
[9] QUESTIONS       completeness checklist for the claim type            code
[10] ASSEMBLE       header, document_set, invariants                     code
```

Four model calls per run. No RAG, no agent, no orchestration, no autonomous loop
— see PRD §8.2 for why each is absent, and note that none of them is excluded for
complexity.

### The three invariants that are enforced, not intended

1. **A structured document cannot reach a model.** `enumerate_passages` raises
   if a `structure_class: "structured"` document carries passages. The FNOL's
   ~100 fields are read by code; only its narrative box becomes a passage.
2. **Nothing uncitable reaches the output.** Every citation must verify exactly
   against its source. Failures are dropped, never hedged — hedged-but-present
   content is worse than absent content because it looks verified. Drops are
   recorded in the audit trail so the drop rule cannot silently flatter a model.
3. **Generation never sees a raw document.** `propose_differences` takes
   `List[Fact]` and has no parameter through which a Document or Passage could
   reach it. `tests/test_llm_boundary.py` asserts no verbatim run from any
   passage appears in the outbound payload.

## 4. Fixtures

| Fixture | Kind | Planted | Purpose |
| --- | --- | --- | --- |
| `claim_000_smoke` | fully synthetic | pair 1 (FNOL narrative vs recorded statement) **and** pair 4 (driver not a listed driver) | The main case. Exercises both the extracted and the deterministic difference paths. |
| `claim_000_zero_conflict` | fully synthetic | **none** | PRD §9.3 category 2. The correct differences list is empty. |
| `claim_001` | real anchor, synthetic documents | pair 1 — direction of travel | **Ready.** Built by `tools/build_claim_001_fixture.py` from the supplied `documents/` and `structured/`. Two documents (FNOL, recorded statement), **two passages**, a 17-entry structured anchor, and a minimal policy record. Three model calls. |

**`claim_000_zero_conflict` is not optional.** PRD §12.2's first decision rule is
stated over false differences on a zero-conflict control, and one fixture with a
planted conflict cannot produce that number. Research §8.2 reports GPT-4o
producing confident summaries of entirely non-existent topics 44% of the time; if
that behaviour shows up here, nothing downstream is trustworthy and no other
metric is worth reading.

`claim_000_smoke` also carries deliberate traps beyond the planted difference:

* an adjuster **leading question** ("So you were stopped at the light...?") that
  the claimant explicitly rejects — attributing it to the claimant is the
  misattribution failure D-020 P3 exists to prevent;
* a **vague time expression** ("That evening, after I had my tea") that must
  remain vague;
* an **independent account that saw nothing** — it states in terms that it did
  not witness the collision, so it takes no position and cannot disagree;
* **ordinary variation** between the FNOL's "about 18:30" and the statement's
  "that evening", which must not be reported as a difference.

`claim_001` plants exactly one difference: the FNOL narrative says the vehicle
was travelling **northbound**, the recorded statement says **southbound**. It
also carries four traps for the *difference* stage, each of which must produce
NO difference:

* **Missing corroboration** — the statement says the vehicle slid; the FNOL
  narrative simply does not mention one. Silence is not a position.
* **Compatible approximation** — 9:43 PM in the FNOL field, "approximately
  9:40 PM" in the statement.
* **Different properties** — "around 25 to 30 mph" (actual) against the anchor's
  POSTED_SPEED_LIMIT of 30 (a road attribute).
* **Non-recall** — the claimant does not recall several details; a stated
  inability to recall takes no position and cannot conflict.

And three traps for the *extraction* stage, all of the strengthening kind: a
belief ("did not believe anyone was injured") must not become a fact, a failure
to observe ("did not see anyone inside") must not become an absence, and an
intention ("intended to report") must not become an act.

The fixture also states **no report date and no FNOL arrival date**, because the
supplied material records neither. Reporting delay and report-date chronology are
therefore not computed, and `not_assessed` says so — an absence must never read
as "no delay".

Any fixture still containing `__TODO__` markers refuses to load, so a placeholder
can never be silently evaluated and reported as a result. See
`data/raw/chicago/README.md` for the responsible-AI constraint on using a real
crash record as an anchor.

### The structured anchor

`claim_001` carries 17 of the 19 entries transcribed from real Chicago crash
data, held at `structured_records.anchor` keyed by the supplier's own fact ids.
Two entries are deliberately withheld from the fact set and recorded under
`provenance.anchor.excluded_entries`: **A007 PRIM_CONTRIBUTORY_CAUSE**, because a
contributory-cause coding is a causal/liability determination rather than one of
the geometry/timing/roadway/vehicle/status attributes the supplied anchor permits;
and **A006 HIT_AND_RUN_I**, deferred as a separate semantic question. The
exclusion is a fixture-authoring decision, not a rule in `src/` — the pipeline
generically reads whatever anchor entries exist.

Three properties keep the rest safe to place beside a claimant's account:

* It is read **deterministically** and cited by `Field` locator. No model sees
  it — `tests/test_llm_boundary.py` asserts no anchor id or field name appears
  in any outbound payload.
* Each derived fact is **attributed to the record**: "The structured crash record
  codes X as Y." The system never asserts that Y is true.
* It is **not ranked above anything**. Difference-prompt rule 7 forbids noting
  that a source is official, independent, or objective, and forbids resolving a
  difference at all.

No person-level attribute is carried into the fixture, and a test enforces that
against both the fixture keys and the anchor's own field names.

## 5. Metrics

From PRD §12.2. **Every metric is reported separately. There is no composite
score**, because a system with excellent recall and broken asserter attribution
would score well and be unusable.

| Metric | Catches |
| --- | --- |
| `fact_recall` | omission |
| `fact_precision` | noise |
| `span_exactness` | a correct fact with a wrong span — unverifiable, and looks verified |
| `asserter_accuracy` | **the highest-consequence error type.** No generic benchmark measures it |
| `hallucination_rate` | forbidden facts emitted, plus spans that resolve to nothing |
| `omission_rate` | completeness, scored separately from accuracy |
| `timeline_ordering_accuracy` | chronology |
| `invented_precision_count` | a vague expression resolved to a timestamp |
| `difference_recall` / `difference_precision` | the differentiator |
| `false_differences_on_zero_conflict_control` | **target: zero** |
| `specificity` | human-rated — vacuous output passes a faithfulness check while asserting nothing |
| `open_question_usefulness` | human-rated — a correct-but-obvious question has no value (D-032) |

The two human-rated metrics are emitted as `requires_human_rating` rather than
approximated. Approximating them would let a vacuous output pass.

An undefined ratio is reported as `null`, never as `0.0` or `1.0`. Difference
recall on the zero-conflict control has no denominator; reporting `1.0` would
flatter it and `0.0` would libel it.

### Matching, and its honest cost

There is **no LLM-as-judge**. A model judging a model makes the evaluation
non-reproducible and reintroduces exactly the non-determinism PRD §8.2 excludes.
Matching is deterministic: gold facts carry an explicit `match_key`; extracted
facts match on passage identity, character-span overlap, and asserter.

The cost, stated rather than buried: **this undercounts semantically correct
extractions worded differently or spanning slightly different text.** Fact recall
will read low for reasons that are not always the model's fault. A brittle number
we can defend beats a smooth number we cannot. `detail.unmatched_output_facts` is
reported so a human can scan what the system produced that gold does not account
for.

The gold `expected_facts` list for *extracted* facts is likewise an **authored
judgement** about what a correct extraction contains. Reasonable people would draw
the boundary differently. This is stated in each gold answer's own disclaimer.

## 6. Decision rules

Committed before any data is seen. `src/evaluation/runner.py` evaluates and
prints them automatically.

| Result | Meaning |
| --- | --- |
| **False differences on the zero-conflict control > 0** | **STOP.** Extraction-then-generate is not sufficient on its own. Investigate before anything else — nothing downstream is trustworthy. |
| **Span exactness or asserter accuracy poor** | **STOP AND RETHINK.** Grounding is not achievable at this level of effort; D-020 P2 would drop most output and the product does not work. This is not a tuning problem. |
| **Fact recall poor, precision good** | **Acceptable.** D-020 explicitly accepts lower recall as the price of drop-if-uncitable. |
| **Everything passes** | Informative, and changes nothing about D-014's gate. |

**Run each fixture at least three times.** Variance across runs is itself a
finding — a capability that works one time in three is not a capability. The
runner's `--runs N` reports mean, min, max, and standard deviation per metric.

## 7. Running it

```bash
python -m pytest tests/ -q                                          # 143 tests, no network

# deterministic path alone — proves seven of nine stages need no model
python -m src.evaluation.runner --fixture claim_000_smoke --client null

# full path against hand-authored recordings — tests the plumbing, not a model
python -m src.evaluation.runner --all --client recorded

# the actual experiment
python -m src.evaluation.runner --all --client live --runs 3
```

`--client live` uses `claude-opus-5` with adaptive thinking and
`output_config.format` structured output, so responses are guaranteed-parseable
JSON rather than prose to be scraped. `model_id` and `prompt_version` are stamped
on every `SynthesisResult`.

**Only `--client live` produces an E1 result.** The recorded responses are
hand-constructed, and `claim_000_smoke`'s are deliberately imperfect — they
contain a fabricated span, an offset drift, and a misattribution, so that the
drop rule, the two drop diagnoses, and asserter accuracy are all exercised by
the test suite. Metrics from `--client recorded` measure the plumbing.

All three fixtures run end-to-end. 143 tests pass, none touching the network.

`claim_001` with `--client null`: 25 deterministic facts, 0 dropped, **0

the deterministic stages stand on their own, which is what PRD §11 claims and
what a null-model run is for. Zero deterministic differences is the correct
result: the supplied policy record plants no policy conflict, and the chronology
