# E2 — Controlled ontology + deterministic neighbourhoods

**Status:** run. 3 live runs, `google/gemini-3.8-flash` via OpenRouter, 2026-09-07. $0.21.
**Artifacts:** `data/generated/e2_ontology/`

## Hypothesis

> If every verified assertion carries a stable entity, event, controlled predicate, and normalized value, deterministic grouping can identify the small sets of assertions that are meaningfully comparable, and the LLM can reason over those neighbourhoods rather than rediscovering claim structure from a flat list.

Both arms run over the **same verified fact set from the same extraction**, so the comparison isolates the difference stage.

## Result

| | Arm A (flat) | Arm B (neighbourhoods) |
| --- | --- | --- |
| facts considered | 57 / 57 / 58 | 57 / 57 / 58 |
| model comparison calls | 1 / 1 / 1 | **8 / 8 / 9** |
| total comparison input | 11,000 / 11,137 / 10,898 ch | **18,613 / 18,607 / 20,832 ch** |
| **per-call** context | 11,000 ch | **~2,300 ch (4.7× smaller)** |
| planted-difference recall | **1.00 ×3** | **1.00 ×3** |
| false differences | 0 ×3 | 0 ×3 |
| CORROBORATING found | **0 — inexpressible** | 9 / 8 / 7 |
| COMPATIBLE found | **0 — inexpressible** | 1 / 2 / 4 |
| CONTRADICTORY found | 1 / 1 / 1 | 1 / 1 / 1 |
| mis-grouped facts | — | **0** |
| entity-linking errors | — | **0** |

**Arm B did not improve difference detection and cost more.** Both arms found the
planted contradiction with three positions and zero false positives, every run.

## What the ontology did do

**Grouping became reproducible.** Neighbourhood keys were **identical across all
three runs — 32/32**. The flat arm's difference subject was still model-invented
(`vehicle_travel_direction` in run 1; earlier runs produced `direction_of_travel`
and `vehicle_direction_of_travel` for the same property). Under the controlled
vocabulary it is `travel_direction`, every time.

**Corroboration became expressible.** The flat model has no slot for agreement —
three sources agreeing the road was wet produces no output at all. Arm B reports
7–9 corroborating relationships per run, each traced to verified citations.

**Two false comparisons were prevented structurally**, not by prompt instruction:

- `approximate_speed` (vehicle, 25–30 mph) and `posted_speed_limit` (roadway, 30
  mph) are different predicates on different entities and never met.
- `occupant_count` (record: 0) and `occupant_observation` (claimant saw nobody)
  stayed apart. A failure to observe is not an absence, and grouping them would
  have invited a corroboration the sources do not support — the exact inference
  the gold `facts_must_not_appear` list forbids.

Similarly `contact_point` on `vehicle_1` (front) never met `contact_point` on
`vehicle_2` (rear-right-corner): same predicate, different entity.

## Honest costs

**Value normalisation is thin.** 12 assertions received a predicate but no
normalised value, so only **3 of 11** comparisons resolved deterministically; the
other 8 needed a model call that a fuller alias table would have avoided. The
lookup tables cover the anchor's vocabulary well and narrative phrasing poorly.

**11 facts could not be grouped at all**, all of them claim-administrative:
policy term, prior-claim count, handler count, reporting dates, document arrival.
They are not assertions about entities or events in the loss, and the Claim 001
vocabulary has no predicate for them. Reported rather than forced into a bucket.

**Arm B costs more tokens in total** — the system prompt is re-sent per call.
Per-call context is 4.7× smaller, which is what matters for model attention, but
billed input is higher.

## Falsification

**What does the ontology + `groupby(entity, event, predicate)` enable that the
flat model cannot provide reliably?**

1. **Reproducible grouping.** 32/32 stable keys versus a model-invented subject
   that varied across runs. The flat model cannot promise that two runs group the
   same facts the same way.
2. **Corroboration and compatibility as first-class outputs.** Structurally
   absent from the flat model.
3. **Structural prevention of category errors** — vehicle speed vs road limit,
   observation vs count, per-vehicle contact points. The flat arm relies on prompt
   instructions for these; here they cannot be compared because they are not in
   the same bucket.
4. **Traceable comparison rationale.** Every comparison states which entity,
   event, and property caused two assertions to be compared.

**What would an actual graph abstraction add beyond this?**

On this evidence, **nothing we currently need.** Every result above came from
four fields on `Fact` and a `groupby`. No traversal, no edge objects, no node
registry, and no graph database was used or missed. Multi-hop questions
("everything asserted about the vehicle the claimant drove") are single filters
at this scale.

**Recommendation: do not build the graph layer.** Revisit only if a fixture
requires multi-hop reasoning across entities, or if relationships need lifecycle
independent of the assertions that produced them.

## Status of each claim

- **Validated:** deterministic quote location solved E1's grounding failure (E1b).
- **Partially supported:** the controlled representation improves *reproducibility*
  and *expressiveness*. It did **not** improve difference recall or reduce cost.
- **Not validated:** that a graph data structure or database is necessary or
  superior. Current evidence says it is not.
